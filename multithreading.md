The one thing that does matter: BatchHandler's asyncio.Lock/asyncio.Task objects are only safe if every call touching a given JobState — reconnect(), submit_entries(), and the poll loop's batch_arrival() — runs on the same loop/thread. So worklist.start() (which kicks off the poll loop) must be scheduled onto the client's own background loop, via client.run_coroutine_sync(worklist.start()), rather than via a bare asyncio.run(...) or some other ad-hoc loop. As long as all interaction goes through that one GollumClient, you get exactly one event loop for everything and it's safe.
